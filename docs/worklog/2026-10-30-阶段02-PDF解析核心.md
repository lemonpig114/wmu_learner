## 一、阶段目标与当时的做法

**目标**:导入温医大课表 PDF → 解析 → 预览校正 → 确认保存 → 显示周课表;优先正确识别课程名/星期/节次/周次/单双周/地点;一门课支持多时段;无法确定的标记待确认;保留手动增删改;重复导入不产生重复课表;导入失败不破坏既有数据;重启后仍可查看。

**当时的做法(已完成部分)**:

1. **先实测版面结构,再写解析**(不凭假设):用提取器把真实 PDF 的字符片段连同坐标转储成 `.analysis-local/token_dump.txt`,据此确定规则。
2. 实测得到的版面规则(全部写进代码注释):
   - 每页 A4 竖向 + 旋转 90°,pdfbox 的 `xDirAdj/yDirAdj` 已校正,可直接用(x 向右、y 向下);
   - 表头(星期一~日)**仅首页出现一次** → 各页共用列坐标,可按"星期列"纵向拼接;
   - 单元格文字 x 与表头标签 x 有固定偏移(实测 −28.9pt)→ 用"最近锚点"归位;
   - 单元格第 1 行为"课程名+类型符号",第 2 行以 `(a-b节)` 开头 → **节次取注记**,不按等距行推(行高随内容自适应);
   - 行高自适应导致单元格可跨页续行 → 按列拼接后切分,续行自动并入;
   - 表外另有"实践课程:"行;页脚为类型图例 + 打印时间,单独处理。
3. **解析核心与 PDF 库解耦**:核心只吃"坐标化文本片段"(`TextRun`),App 内用 pdfbox-android 2.0.27.0,单测用桌面 pdfbox 2.0.37(同源 2.0.x)→ 真实文件可在 JVM 上反复验证。
4. **隐私**:首页标题区含姓名/学号,按 y 过滤并**只取"学期"token**,其余丢弃;测试含隐私回归断言。
5. **不可解析不猜测**:周次表达式解析失败返回 null 并计入"待确认"。

### 4.3 修改与否决记录

- **否决 OCR 方案**:实测为文字型 PDF,OCR 属过度设计。
- **否决按等距行推节次**:实测行高随内容自适应,改为读 `(a-b节)` 注记。
- **否决硬编码列宽**:改为由表头锚点 + 最近邻归位,以适应不同学期/专业版式。
- **否决"只靠文件 hash 去重"**:同一课表 3 个副本 MD5 全不同(打印时间差异),必须做解析后语义比对。
- **修改(自身 bug,已修正并留档)**:学期提取原被标题区 y 过滤误杀,且原实现会把姓名/学号一并存入 → 改为仅取学期 token(隐私风险修复)。
- **修改(单双周摘要语义)**:`13-15周(单),16-17周` 的摘要由"单"改为"混合"(单周分量与普通分量共存)。
- **修改(测试期望值)**:`4-6周(双)` 的正确展开是 4、6(原测试期望误含 5),已按真实语义修正。
